# Requirements

### Overview & Goals
Improve the user experience by eliminating the "login flicker" during navigation, adding playful cat-themed loading animations for long-running tasks, and implementing a "Socke" dark-mode gimmick.

### Scope
- **In Scope**:
    - Fixing auth-state flickering in `admin.html`, `account.html`, and `service.html`.
    - Implementing a CSS/SVG "Snoozing Cat" loading animation.
    - "Socke" dark-mode gimmick: branding changes to "Socke" and `socke.png` only when dark mode is enabled.
    - Integrating loading states into graph and list rendering.
- **Out Scope**:
    - Global rebranding (project name remains "Sanshain" in light mode).
    - Renaming the Rust crate or binary name.
    - Renaming the database file or internal API endpoint paths.
    - Renaming storage keys (e.g., `sanshain_token`).

# Technical Design

### Current Implementation
- **Auth**: Pages show the login screen by default and only hide it after an asynchronous token check, causing a "flicker".
- **UX**: There is no visual feedback during graph generation or large service list loading beyond static "Loading..." text.
- **Branding**: The project is branded as "Sanshain" with a sun logo (`sonne.png`).

### Proposed Changes

#### 1. Auth Stability & Flicker Prevention
- **Loader Overlay**: Add a full-screen `#app-loader` to `layout.html` and static pages that is visible by default.
- **Content Hiding**: Set `login-screen` and `dashboard` containers to `hidden` in the base HTML.
- **State Transition**: Only hide the loader and reveal the appropriate container in the `checkSession()` callback after the `/auth/me` response is received.

#### 2. Snoozing Cat Animation
- **SVG Cat**: A simple, minimalist cat SVG with closed eyes and a "breathing" body animation.
- **"Zzz" Effects**: Floating "Zzz" elements using CSS `@keyframes` with staggered delays and upward translation.
- **Shared Utility**: `static/js/common.js` will export `showLoader()` and `hideLoader()` to manage the transition across all pages.

#### 3. Socke Dark-Mode Gimmick
- **Dynamic Rebranding**: Update `applyTheme(theme)` in `static/js/common.js` to also perform rebranding.
- **Dark Mode Activation**:
    - If `theme === 'dark'`:
        - Replaces "Sanshain" with "Socke" in `<title>`, headers, and footer via DOM manipulation.
        - Replaces `sonne.png` with `socke.png` in all `<img>` tags.
    - If `theme === 'light'`:
        - Reverts all text and image references back to "Sanshain" and `sonne.png`.
- **Note**: This is purely a UI gimmick and does not affect storage keys, API paths, or documentation.

### File Structure
- `static/js/common.js`: Shared loader logic, cat animation, and dark-mode gimmick.
- `templates/layout.html`: Global loader placeholder and auth-state stability.
- `static/admin.html`, `static/account.html`, `static/service.html`: Auth initialization.

### Risks
- **Image Missing**: `socke.png` must be provided in `static/images/`.
    - *Mitigation*: Fallback to `sonne.png` or alt text "Socke" if missing.

# Testing

### Validation Approach
Verify the changes by performing cross-page navigation and observing the new transitions and branding.

### Key Scenarios
- **Cold Boot (No Token)**: Open `/admin.html` -> See cat loader -> See Login form (no flicker of dashboard).
- **Authenticated Navigation**: Log in -> Navigate between Service and Admin -> See cat loader briefly -> See Dashboard (no flicker of login).
- **Large Graph Loading**: Select a complex branch in Graph view -> See cat loader -> See Graph rendered.
- **Dark Mode Gimmick Check**: Toggle dark mode -> Verify text changes to "Socke" and logo changes to `socke.png`. Toggle light mode -> Verify it reverts to "Sanshain" and `sonne.png`.
