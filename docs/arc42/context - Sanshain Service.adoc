=== Whitebox Sanshain Service

image::context - Sanshain Service.svg[Whitebox Sanshain Service]

==== Motivation

Hexagonal layering: the HTTP API and the MCP Server translate requests into use cases; Application Services hold the business rules and depend on traits in the domain layer (models, permissions, ports - shared by every box, so not drawn). Infrastructure adapters implement those ports: Auth Providers for human login and Persistence for storage. Spec parsing is kept apart from the use cases so that the free validator and the publish path apply identical rules. Webhooks are their own flow: the use cases write events into an outbox in the same transaction as the fact, and a background worker delivers them, so a slow receiver never slows a provide. Telemetry is fed by middleware layers on every request rather than by explicit calls. Line kinds: business (catalog flows), admin (operation and login), telemetry (traces, metrics), async-outbound (pushes that leave the request).

==== Contained building blocks

[options="header"]
|===
|Name |Responsibility

|Application Services
|Use cases (src/application): provide and require specs, version-line rules, release branches and graph timelines, Backstage catalog context, reports, administration, authentication with token scopes and permission checks, and the MCP catalog answers. Depends only on domain ports.

|Auth Providers
|Adapters for human login (src/infrastructure/*_provider.rs, tls.rs): local Argon2 accounts, LDAP/AD bind and group lookup with connect and operation timeouts, and the OIDC authorization code flow.

|HTTP API
|Axum router, handlers and middleware (src/presentation, src/lib.rs): REST endpoints for provide/require/catalog/report/admin/auth, token and session authentication with full or read-only token scope, permission guards per route, SSE/WebSocket live updates, webhook management and the /metrics endpoint.

|MCP Server
|Model Context Protocol endpoint for AI clients (src/presentation/mcp.rs, src/application/mcp_service.rs, docs/mcp.md): POST /mcp, Streamable HTTP, stateless, behind a read-only API token; tools list_services, describe_service, find_endpoint, get_spec, get_graph, diff_versions and blame answer from the catalog only, rate-limited per token and size-budgeted per answer.

|Persistence
|Implements the SpecRepository port: a Moka cache with a 10 s data TTL in front of interchangeable sqlx repositories for SQLite and PostgreSQL, including schema migrations, the webhook outbox tables and the SQLite snapshot.

|Spec Parsers
|OpenAPI, AsyncAPI and Protobuf handling (src/openapi.rs, src/asyncapi.rs, src/proto.rs): validate documents, extract version and endpoints, cut endpoint snippets and detect breaking changes.

|Telemetry
|OpenTelemetry tracer with OTLP exporter (src/infrastructure/telemetry.rs) and the Prometheus recorder behind /metrics; fed by the tracing and metric layers of every request.

|Web UI
|Browser dashboard (static/*.html, static/js, askama templates): producers, consumers, version timelines, diffs, dependency graph with peripheral resources and catalog context, reports, audit, observability, webhook and admin pages, account page with API tokens, plus the anonymous spec validator.

|Webhooks
|Outbound events (src/application/webhook_service.rs, webhook_delivery.rs, src/infrastructure/webhook_sender.rs, ADR-0009): decides which hooks a fact reaches (global hooks plus the hooks of the Producer and of its Consumers along the require graph), writes the deliveries to the outbox with the fact, and a worker claims due deliveries, renders JSON, Slack or Teams bodies, signs them with HMAC-SHA256 and POSTs them with backoff for 24 hours; egress is limited to the admin's host allow-list.
|===
