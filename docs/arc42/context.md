### Context

![Context view](<context.svg>)

Sanshain sits between the build pipelines of many microservices: Build Tooling publishes specs and Backstage catalog files as Producer and fetches pinned endpoint snippets as Consumer, while people use the web dashboard to inspect versions and the dependency graph and AI clients ask the catalog over MCP. Human login can be delegated to LDAP/AD or an OIDC provider; machine clients always use API tokens, full or read-only. State lives in SQLite or PostgreSQL, a Backup Job pulls consistent snapshots, traces and metrics go to an optional observability stack, and every catalog fact is pushed as a signed event to the webhook receivers on the allow-list.

#### Communication partners

| Partner                 | Description                                                                                                                                                                                                                                                     | Input                                                                          | Output                                                                                           |
|-------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------|
| AI Client               | Claude Code or another MCP client that asks the catalog questions: list and describe services, find an endpoint, read a spec, walk the graph, diff and blame versions. Read-only, rate-limited, catalog data only.                                              | MCP tool calls with a read-only API token (Streamable HTTP) (Sanshain Service) | –                                                                                                |
| Backup Job              | Helm CronJob (or any scheduler) that downloads a consistent SQLite snapshot nightly and keeps the last N files; on PostgreSQL a pg_dump CronJob takes its place and never talks to Sanshain.                                                                    | GET /admin/backup/sqlite with a full API token (HTTPS) (Sanshain Service)      | –                                                                                                |
| Build Tooling           | Maven plugin, cargo-sanshain, Go CLI, JS client/GitHub Action and Conan plugin; publish specs and the Backstage catalog-info.yaml for a Producer and fetch pinned endpoint snippets for a Consumer during CI builds.                                            | provide / require / report (REST, API token) (Sanshain Service)                | –                                                                                                |
| LDAP / Active Directory | Optional corporate directory that authenticates human users and supplies group memberships.                                                                                                                                                                     | –                                                                              | bind + group lookup (LDAP/LDAPS) (Sanshain Service)                                              |
| Observability Stack     | Optional OpenTelemetry collector receiving traces and Prometheus scraping request metrics.                                                                                                                                                                      | OTLP traces (gRPC) / Prometheus scrape /metrics (Sanshain Service)             | OTLP traces (gRPC) / Prometheus scrape /metrics (Sanshain Service)                               |
| OIDC Provider           | Optional SSO identity provider for human login.                                                                                                                                                                                                                 | –                                                                              | authorization code flow (HTTPS) (Sanshain Service)                                               |
| User                    | Developer, maintainer or administrator who browses producers, versions, diffs and the dependency graph, and manages users, roles and settings.                                                                                                                  | web dashboard, graph, admin (HTTPS) (Sanshain Service)                         | –                                                                                                |
| Webhook Receivers       | Any URL on the admin's allow-list, a Slack or a Teams incoming webhook: receives the signed events Sanshain emits (version published or deprecated, provide rejected, dependency recorded, branch cut, catalog recorded), retried from the outbox for 24 hours. | –                                                                              | signed event POSTs: JSON envelope or Slack/Teams message (HTTPS, HMAC-SHA256) (Sanshain Service) |

#### Building blocks

| Name             | Responsibility                                                                                                                                                                                                                                                     |
|------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Database Server  | Stores specs, version lines, endpoints, pins, branches, users, roles and audit log. Embedded SQLite by default, PostgreSQL for larger deployments.                                                                                                                 |
| Sanshain Service | Central registry for OpenAPI, AsyncAPI and gRPC specs: Producers publish versioned specs, Consumers download only the endpoints they pin, and the resulting dependency graph is tracked, shown, pushed as signed webhook events and served to AI clients over MCP. |
