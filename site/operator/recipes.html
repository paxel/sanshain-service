One task per section, each with the command, the answer a 2.6.0 instance gave, and where to read more. The answers are the recordings of An operator's story; where a task is not in the story, the expected answer is quoted from the Maintenance API reference. Administrative routes take a session token (SESSION from POST /auth/login), never an API token, with one exception noted below.

SESSION=$(curl -s -X POST $SANSHAIN/auth/login -H "Content-Type: application/json" \

Change the admin password



  
The answer is a new session; every other session of the account ends.

  
curl -s -X POST $SANSHAIN/auth/change-password \
  -H "Authorization: Bearer $SESSION" -H "Content-Type: application/json" \
  -d '{"old_password":"…","new_password":"…"}'

Set the webhook allow-list



  

    Replaces the list. http:// in front of a pattern admits plain HTTP to that host.
  

  
curl -s -X POST $SANSHAIN/admin/settings/webhook-allowed-hosts \
  -H "Authorization: Bearer $SESSION" -H "Content-Type: application/json" \
  -d '{"hosts":["hooks.slack.com","http://n8n.corp.internal"]}'

  
Recorded (story, step 5)

  

  

    Webhooks: the allow-list ·
    POST /admin/settings/webhook-allowed-hosts
  





Register and test a hook



  

    The secret is in the registration answer only. For a Producer's or Consumer's own hook use
    /admin/producers/{name}/webhooks or
    /admin/consumers/{name}/webhooks with the same body.
  

  
curl -s -X POST $SANSHAIN/admin/webhooks \
  -H "Authorization: Bearer $SESSION" -H "Content-Type: application/json" \
  -d '{"url":"https://hooks.slack.com/services/…","format":"slack","event_types":["version.published","provide.rejected"]}'
curl -s -X POST $SANSHAIN/admin/webhooks/1/test -H "Authorization: Bearer $SESSION"

  
Recorded (story, step 6)

  

  

  

    Webhooks: hooks in three scopes ·
    POST /admin/webhooks

Rotate a webhook secret



  

    Not in the story. A new secret, answered once, signs every later delivery; audited as
    WEBHOOK_SECRET_ROTATED.
  

  
curl -s -X POST $SANSHAIN/admin/webhooks/1/rotate-secret -H "Authorization: Bearer $SESSION"

  
Expected answer

  
HTTP/1.1 200 OK
{ "webhook": { "id": 1, "secret_hint": "…", … }, "secret": "whsec_…" }

  

    POST /admin/webhooks/{id}/rotate-secret
  





Redeliver a delivery



  

    Not in the story. Find the delivery in the log; redeliver resets it, a dead one included, for
    one more attempt with the same event id.
  

  
curl -s "$SANSHAIN/admin/webhooks/1/deliveries?limit=50" -H "Authorization: Bearer $SESSION"
curl -s -X POST $SANSHAIN/admin/webhooks/1/deliveries/1/redeliver -H "Authorization: Bearer $SESSION"

  
The log, recorded (story, step 6)

  

  
Expected answer of the redeliver

  
HTTP/1.1 202 Accepted
{ "id": 1, "hook_id": 1, "event_id": "…", "status": "pending", "attempts": 0, "redelivered_at": "…", … }

  

    Webhooks: retries and redelivery ·
    POST …/deliveries/{delivery_id}/redeliver
  





Pause, resume or delete a hook



  

    Not in the story. A paused hook's deliveries stay pending and go out on resume; deleting removes
    the hook and its delivery log.
  

  
curl -s -X PATCH $SANSHAIN/admin/webhooks/1 \
  -H "Authorization: Bearer $SESSION" -H "Content-Type: application/json" -d '{"paused":true}'
curl -s -X DELETE $SANSHAIN/admin/webhooks/1 -H "Authorization: Bearer $SESSION"

  
Expected answers

  
HTTP/1.1 200 OK            (PATCH: the hook, with "paused": true)
HTTP/1.1 204 No Content     (DELETE)

  

    PATCH /admin/webhooks/{id} ·
    DELETE /admin/webhooks/{id}

Delete a version



  

    Not in the story. The audited escape hatch for administrators and the Producer's maintainers;
    the answer lists the Consumers that pinned it, whose pins now dangle until the number is
    re-provided. Check them first with …/dependents.
  

  
curl -s "$SANSHAIN/admin/producers/payments/versions/openapi/2.1.0/dependents" -H "Authorization: Bearer $SESSION"
curl -s -X DELETE $SANSHAIN/admin/producers/payments/versions/openapi/2.1.0 -H "Authorization: Bearer $SESSION"

  
Expected answer of the delete

  
HTTP/1.1 200 OK
{ "deleted": "2.1.0", "dependents": [] }

  

    Administration: deleting a version ·
    DELETE /admin/producers/{name}/versions/{api_type}/{version}
