2.18.0 tells why a version exists and where it goes: the git branch of a build, a patch proposal on maintenance branches, free moves for Consumers, versioned require sets, and Product releases from the Helm pipeline. This page is the short version of the changelog, sorted by who notices a change.

Before you upgrade

Nothing stops a working setup. Two things behave differently for those who use Products: a pasted Chart.yaml with a version also creates a release, and only the highest chart version sets the Product's members; the admin paste answers the release beside the member lists ({chart_version, outcome, members}) instead of the bare member lists. A script that reads that answer needs the new shape. The database migrations run at start, forward only, as always.

For operators

  • Branch Names on the General tab: the company's branch naming patterns, which read where a branch merges to and which branches are maintenance branches, with a test field.
  • First Day of the Week on the General tab: the day the weeks of the statistics start, Monday until it is set.
  • The statistics page bands every second week on its daily charts, draws each domain of the sankey "Dependencies between domains" in its graph colour, and filters the Catalog by whether a system has a catalog push (Reports).
  • A Product Maintainer pushes the umbrella chart from the Helm pipeline with a full API token, and each chart version becomes a release with a sheet, a CSV export and a compare (Product releases, Roles).

For Producers and Consumers

  • A provide carries the git branch of its build (git_branch, and git_target_branch on a pull or merge request build); the version row shows it as feature/master/login → master (CI integration).
  • A refused provide from a release, bugfix or hotfix branch, or with a stream tag, is proposed a patch in its own minor: 2.6.0 gives 2.6.1, not 2.24.0 (maintenance branches).
  • A require names a free move in the header X-Sanshain-Upgrade: the newest version that serves every endpoint the Consumer requires of its Pin in the same shape. The Consumer page shows the newer versions per Pin (free moves).
  • Requires send requires_hash, and each new hash from a trunk or tag require gets the Consumer's next require-set version (require-set versions). The Consumer page shows them in a strip, the Producer page a strip of who pins each version.
  • The Producer page lists per version the endpoints it added, changed, removed or newly deprecated against the highest GA below it.
  • Services before 2.18.0 refuse the new fields (422 on a provide or a bundle, 400 on GET /require).

Security

No security changes in 2.18.0.
